# ADR-003：不实现剪映官方 agent 协议（P3 G1–G6）

- 状态：已决定（不再作为缺口追踪）
- 日期：2026-10-18
- 相关：`docs/reference/jianying-11.6-feature-map.md`、`docs/vision/offline-intelligent-editing.md`

## 背景

计划 P3 条目写的是"官方协议覆盖 G1–G6"。调研 剪映专业版 11.6 时确认，其内部
`Resources/canvas_agent` 带 19 个技能与 4 段 agent 提示词，配套一个
`jianying-agent-cli.exe`，调用时要求环境变量 `JIANYING_AGENT_RUNTIME_TOKEN`；
本地 API 端点 `127.0.0.1:50194` 未授权时返回 401。

也就是说：要"覆盖"这条协议，必须先拿到并使用剪映自身的运行时令牌。

## 决定

**不实现。** G1–G6 从"待办缺口"改为"明确排除"，并在能力清单里以
`out_of_scope` 语义登记（见 `provenance/PYJYD_API_COVERAGE.json` 的同类做法）。

## 理由

1. **鉴权红线**：读取或伪造 `JIANYING_AGENT_RUNTIME_TOKEN`、绕过签名，
   属于破解他人产品授权边界，不是"集成"。
2. **可持续性**：这类私有协议随客户端版本变化，且需要客户端常驻；
   与之耦合会把"无客户端"这个核心卖点变成依赖客户端。
3. **收益递减**：本仓库已有的公开面（草稿线格式 + ffmpeg 渲染 + MCP）
   已能完成目标里的全部编辑动作，官方协议主要提供的是"在客户端内执行"，
   而我们的目标恰恰是**不启动客户端**。

## 后果

- 正向：运行时零剪映依赖；发布物可在没有客户端的机器上完整自检
  （`jianying selftest` 7/7）。
- 负向：无法驱动客户端的原生导出与部分 UI-only 能力；**权威成片导出仍需
  在剪映内完成**，本仓库只提供预览级渲染。这条限制已经写在 README 的
  "边界（如实）"一节。
- 若是未来确实需要客户端内执行，应通过**用户显式授权**的官方接口进行，
  并重新提交 ADR，而不是在代码里隐式绕过。

## 替代方案（已评估）

| 方案 | 结论 |
|---|---|
| 用其他工具代签/伪造请求 | 拒绝：鉴权红线 |
| 仅做 HTTP 探测（不回退到绕过） | 已做：`runtime.status` 只报可观测事实，不含凭据 |
| 依赖第三方 headless 项目 | 拒绝：其许可为非商业学习用途，且我们不需要其实现 |
